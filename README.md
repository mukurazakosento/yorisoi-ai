# よりそいAI / iOS Prototype

高齢者が「したいこと」を入力すると、AIが画面を確認しながら、
次に取るべき操作を通知で案内するプロトタイプです。

## 想定フロー

1. よりそいAIを開く
2. 「孫に写真を送りたい」と入力
3. 画面共有を許可
4. ホーム画面へ戻る
5. ScreenCaptureKitで画面フレームを取得
6. Vision OCRで画面上の文字を解析
7. 画面状況に応じて通知で
   - 「LINEを開いてください」
   - 「『孫』のトークを開いてください」
   - 「『＋』ボタンを押してください」
   - 「写真を選んでください」
   と案内
8. 目的達成

## 必要環境

- Xcode
- iOS 27+
- 実機iPhone
- 通知を許可
- 画面共有を許可

AppleのScreenCaptureKit公式サンプルも、iOS 27以降でフルディスプレイの画面取得を行い、
`screen-capture` のバックグラウンドモードを利用しています。

## Xcodeでの設定

1. Xcodeで「iOS App」を新規作成
2. Deployment Targetを iOS 27.0 以上にする
3. このリポジトリのSwiftファイルをプロジェクトへ追加
4. `Info.plist` の内容を反映
5. Signing & Capabilities で Apple Development の署名を設定
6. 実機iPhoneを選択してRun
7. アプリ内で「案内を開始」
8. システムの画面共有UIで「画面全体」を許可
9. ホーム画面へ戻る
10. 通知で操作案内が出ることを確認

## 重要

このコードの「AI目的理解」は現在ルールベースです。
`InstructionPlanner` をLLM/APIに置き換えると、
自然文から実際の操作手順を生成する構成にできます。

また、現段階ではOCRによって画面内の文字を確認し、
キーワードでステップを進めます。

本番版では、
- 画面構造理解
- 画像認識
- UI要素位置推定
- LLMによるタスク計画
- 個人情報マスキング
- アプリごとの操作モデル
などを追加する想定です。

## セキュリティ

`PrivacyGuard` は「パスワード」「口座番号」などの文字を検出すると
画面解析を一時停止する試作です。

本番ではOCRだけに頼らず、
入力欄の種類・OS情報・アプリ情報など複数のシグナルを組み合わせます。

## できないこと

iOSの公開APIでは、よりそいAI自身が勝手に終了して
ユーザーのホーム画面へ強制遷移することはできません。
そのため、画面共有開始後にユーザーがホーム画面へ戻る操作を行います。

また、このプロトタイプは他アプリを自動操作しません。
通知によって「次に何をするか」を案内するところまでです。
